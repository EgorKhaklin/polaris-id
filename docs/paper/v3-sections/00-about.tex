\section*{Before you read}
\addcontentsline{toc}{section}{Before you read}

Polaris is an attempt to build identity infrastructure in which important claims do not have to
be trusted merely because a central application says they are true. Authority, state, history,
privacy boundaries and the system's own behaviour are progressively exposed to independent
verification and constrained by layers that do not share each other's assumptions. Each layer exists
because the layer inside it could be entirely correct and still fail to prove what a society needs
to know. That progression is the spine of the paper.

The rule the project follows is that the unit of progress
is a new external dependency survived: a named wallet, a named conformance profile, a named relying
party, a defect filed by somebody who is not the author. The count of invariants, versions and lines
is not progress and the repository's scoreboard refuses to record it. This paper follows the rule.
Where it reports internal evidence, it says so, and it keeps that evidence out of the sentences that
report the other kind.

This document is a map of that progression, drawn at version \code{1.0.0-rc.7} of the system
(20 September 2026). The system has kept moving since. A later event that changes what a reader
should believe is dated where it appears; everything else later work corrected or learned is
recorded in \evidencerecord{} and does not redraw the map. That record also holds the history of
this report's own versions, the corrections, and how every count was measured, on the tree and not
copied from earlier documents; where the repository's documents disagree with its code, the code
wins. Every term of art is in the glossary, Appendix~\ref{app:glossary}.

\subsection*{What this is, for whom, and what it asks}

In plain terms: Polaris is software for issuing and checking identity credentials, built so that
the people who run it cannot quietly rewrite what it says, watch the people it describes, or turn
it against them. It is for the engineers, reviewers and institutions who have to decide how such a
system should be built, and it has never held a real person's data. What it asks of a reader is a
test: walk the stranger's path in Section~\ref{sec:use}, run a verifier against it, or attack it,
and report what happened. The first wallet written by strangers to try it refused it before it accepted
it; Section~\ref{sec:outside} tells how.

\subsection*{Five marks}

Every capability carries one of five marks, so that code that runs is never confused with an
intention, and so that a thing the author has tested is never confused with a thing somebody else
has. In the running text an implemented path carries no mark, since most of this map is exactly
that; a mark appears there only where a claim is something else. Tables mark every row.

\begin{description}
  \item[\sImplMark] A path that runs at \code{1.0.0-rc.7}, exercised by a test or a drill in continuous
    integration, and pinned by an invariant check that fails the build if it stops being true.
  \item[\sExp] A path that runs but is limited in a way the repository itself names: not covered by
    CI, notional in scale, or dependent on a backend that CI simulates.
  \item[\sExt] A property the repository implements and tests internally but that no external
    party has audited, attacked, deployed or independently re-implemented.
  \item[\sWit] A path that a named party outside the repository has actually exercised, on a date,
    with a result that can be pointed at: a wallet, a conformance service, a published test corpus.
    It is given only for a filled row of the repository's scoreboard, and never means audited,
    certified or piloted. Three things carry it in this paper.
  \item[\sFut] A proposal: a roadmap row, a design note, or an idea that exists only in this paper.
    It is not code.
\end{description}
