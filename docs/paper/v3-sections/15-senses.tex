\section{Errors become new senses: the history of self-correction}
\label{sec:senses}

\subsection{Formal truth is not intended truth}

A check can be perfectly green while proving the wrong proposition. A signature can exist without
ever being verified. A benchmark can report thousands of verifications per second while counting
database writes. A two-witness guarantee can be certified on the strength of one witness that
happened to be absent. Seventy-one of seventy-five checks can pass on a tree where the property
each names has been commented out. The suite that proves one identity per person can be the thing
violating it. Every one of those sentences describes a state Polaris was actually in, at a version
the changelog names, and every one was found by running the system rather than reading it, or by an
outside reader who did not share the author's assumptions. The project's method for this is a
loop: an observation, a failure, a correction of the model of what the mechanism really proves, a
new invariant with a detection test, and a permanent new sense that the failure class cannot recur
unseen. Invariants accumulate and are never deleted. At \code{1.0.0-rc.7} there are 313 of them, and
twelve drills whose only job is to attack the layer they belong to.

\subsection{Selected corrections, from the record, up to Version 2}

Each row is a mechanism that was technically valid and did not prove what was intended, the version
that found it, and the sense it left behind. None of these is embarrassing; each is the method
working. Version 2 carried this table, and it is kept.

\subsection{Since Version 2: the instruments were asked whether they would notice}

Between \code{v9.357} and \code{1.0.0-rc.1} the loop was turned on the verification layer itself.
The question changed from \emph{does it pass} to \emph{would it notice}, and the answers below are
the record. Most of these rows are about the tests rather than the system, which is the point: a
guarantee is believed because a check says so, and the checks are written by the same hand as the
code.

\subsection{Multiple observers of one claim, and the first from outside}

The pattern behind the tables is that Polaris increasingly refuses to let one observer decide
whether a claim holds. A cryptographic verdict has two implementations and one published corpus. A
check has a detection test that proves it can see its own violation, with a control. A drill runs
the path instead of reading it, and counts its cases. An attack tries to break the defence with the
real code. A fuzzer explores the input space the drills hand-picked. Twelve mutation drills ask
whether the tests would notice their subject going missing. An outside review at \code{v9.331} found
six things the author's own instruments had not, and five became invariants within eight versions.
Continuous integration carries all of it on every push. None of these observers shares the others'
assumptions, and that is the point: a green test is not proof that the test asked the right question,
but many differently-built observers agreeing is much harder to fool than one.

Version 2 proposed a seventh observer that would live outside the repository altogether, under the
name Myrmex, and it remains a proposal (Section~\ref{sec:research}). What arrived instead was
plainer: a wallet somebody else wrote, and a conformance service somebody else runs. The wallet
refused a certificate that eleven conformance modules, 142 package tests, a mutation drill over every
refusal and every check in the invariant layer had passed over. That is the whole argument for the
operating contract in one event. Every observer inside the repository inherits the author's model of
what a request-signing certificate has to contain; the first observer that did not inherit it found
the gap in seconds.
