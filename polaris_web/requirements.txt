# polaris_web/requirements.txt — pinned RUNTIME dependencies only
#
# v9.05 / Wave 1 / C3 introduced a single pinned file. v9.105 split it:
# this file is the production runtime surface (what ships in the Docker
# images), and the test-only tools (Hypothesis, pytest, Playwright) moved
# to requirements-dev.txt. The production image must not carry test
# frameworks — they are dead weight and extra CVE surface in prod (a
# pytest CVE, CVE-2025-71176, is exactly why this split happened).
#
# Versions captured from the working dev venv on 2026-05-14 (Polaris
# v9.05 ship); bump intentionally.
#
# Usage (run the app):
#   python3 -m venv polaris_web/venv
#   source polaris_web/venv/bin/activate
#   pip install -r polaris_web/requirements.txt
#
# To also get the test tooling, install requirements-dev.txt (which
# pulls this file in via `-r requirements.txt`).
#
# CI installs requirements-dev.txt (it runs the suites); the Dockerfiles
# install THIS file only; pip-audit gates on THIS file (the runtime
# surface) in .github/workflows/ci.yml.

# ---- Runtime: Redis client for cross-worker rate limiting (v9.40) ----
# Auto-selected by security.py when POLARIS_REDIS_URL is set + the URL
# is reachable. Without this package, security.py falls back to the
# in-memory backend (each gunicorn worker holds its own bucket).
# Required for accurate per-IP rate limits under POLARIS_WORKERS>1.
# v9.190 (roadmap P1.8): the 5.x to 8.x major taken with its own test pass
# (the Redis-backed limiter tests run against a real Redis in CI, and the
# abuse drill runs the Lua sliding window through it). Exact pin, so the
# image and the runner install the same client; 8.x speaks RESP3 by default
# and retries by default, the latter overridden in security.py.
