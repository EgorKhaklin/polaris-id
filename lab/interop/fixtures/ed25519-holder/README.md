An SD-JWT VC whose holder key (`cnf.jwk`) is an Ed25519 key, for testing a wallet or verifier whose holder keys are Ed25519 only. It is generated by `make_fixture.py`, not from an exchange.

| File | What it is |
|---|---|
| `credential.dc+sd-jwt` | The issuer-signed SD-JWT VC, header `typ` `dc+sd-jwt`, in the stored form `<issuer-jwt>~<disclosure>~<disclosure>~<disclosure>~`: a trailing `~`, no Key Binding JWT. The issuer JWT is signed ES256; its `x5c` holds one test leaf. |
| `credential.vc+sd-jwt` | The same credential with header `typ` `vc+sd-jwt`. Only `typ` and the issuer signature differ. |
| `trust-anchor.pem` | The test CA that signed the leaf in `x5c`. Trust it as the issuer's root. |
| `holder-private.test-only.jwk.json` | The Ed25519 holder key, private `d` included. TEST ONLY, published on purpose so you can sign your own Key Binding JWTs or proofs with it. Never trust it for anything. |
| `example-presentation.dc+sd-jwt` | `credential.dc+sd-jwt` with `given_name` and `family_name` disclosed (`birthdate` withheld) and a Key Binding JWT signed `EdDSA` by the holder key, over the nonce and audience in `fixture.json`. |
| `fixture.json` | The instant, `exp`, issuer, `vct`, nonce, audience, claims, the holder's public JWK and its `did:key`, and this list of files. |

The credential carries `iss` `https://issuer.example`, a `vct`, `iat` 2026-10-01, `exp` 2099-12-31, three selectively disclosable claims (`given_name`, `family_name`, `birthdate`) and `cnf.jwk` `{"kty": "OKP", "crv": "Ed25519", "x": ...}`. The CA and leaf are valid from 2026-01-01 to 2099-12-31. The Key Binding JWT uses `alg` `EdDSA` (RFC 8037) and `typ` `kb+jwt`; its `sd_hash` is the base64url SHA-256 of the presentation up to and including the last `~`.

Every key is TEST material derived from public seeds in `make_fixture.py`: anyone can regenerate every byte, and nobody may trust any of these keys. Regenerate with `python3 make_fixture.py` (cryptography 44 or later); `git diff` is then empty. `test_fixture.py` checks the files with `cryptography` alone: the issuer signatures under the test CA, the disclosures in `_sd`, `cnf.jwk` against the private key's public half, the example Key Binding JWT and its `sd_hash`, the two `typ` forms, `exp`, and that a rerun reproduces every file byte for byte.

polaris-oid4vp does not verify this presentation: it accepts ES256 key binding only today, and an EdDSA option is not built yet. It checks the issuer part and refuses at the holder key (`kb_cnf`); `test_fixture.py` holds that sentence true.
