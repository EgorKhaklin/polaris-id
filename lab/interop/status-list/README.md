# status-list: outside Token Status Lists, decided by polaris-oid4vp

The other walks in this directory send presentations into the verifier. This one checks the
verifier's revocation half: `polaris_oid4vp.status.decide`, the function a relying party calls on
a fetched Token Status List (`draft-ietf-oauth-status-list`), against lists made outside Polaris.

| Source | What it is | How it reaches `decide` |
|---|---|---|
| draft-ietf-oauth-status-list-21, Section 4.2 and Appendix C | the byte arrays of Section 4.2 and the test vectors of Appendix C: 1, 2, 4 and 8 bits, 2^20 entries each | the vectors carry no signature, so each `lst` goes into a token `decide.py` signs with a key of its own |
| the draft's signed example (Section 8.2) | a Status List Token signed ES256 under kid `12` | as published, checked with the example key the draft's authors publish in their repository (`src/util.py`) |
| [`@sd-jwt/jwt-status-list`](https://www.npmjs.com/package/@sd-jwt/jwt-status-list) 0.19.0 (OpenWallet Foundation) | six lists at 1, 2, 4 and 8 bits, from 4,096 to 2^20 entries, the largest at 10% revoked | the library builds, compresses and shapes each list; `owf/mint.mjs` fills it from a seeded generator and signs it |

## Run it

    lab/interop/status-list/run.sh                                         # the newest release
    POLARIS_OID4VP=packages/polaris-oid4vp lab/interop/status-list/run.sh  # the tree

Needs Python 3 and Node 20 or newer. It downloads the draft and the authors' `src/util.py`, each
pinned by SHA-256, and installs the library from `owf/package-lock.json`. Under a minute. It exits
0 only if every status matches and every control is refused.

## Controls

| Control | Refused as |
|---|---|
| an index one past the end of the draft's 8-bit vector | `index` |
| the draft's signed example under an unrelated key | `signature` |
| a library token signed by a key the verifier does not trust | `signature` |
| a library token that expired an hour ago | `expired` |
| a library token decided for another URI than its `sub` | `sub_mismatch` |
| an index one past the end of a library list | `index` |

## Result (2026-10-04)

Against the tree: every status matched (5,447 decisions) and every control was refused.
The draft's example is reported `stale` (issued 2023-06-16, `ttl` twelve hours) and still
decided: staleness is the caller's policy, not a refusal.

Against the published 1.0.0rc15, one list failed: the library's 2^20 entries at 10% revoked, a
97,142-byte payload, refused as `malformed`. The verifier held a status list token's payload to
64 KiB, but the compressed list is inside the payload, and the draft's own size table (Appendix
B) puts 2^20 entries at 10% revoked at 67.6 KB compressed. The payload is now bounded by the
token's size (2 MiB) and keeps its depth bound; `test_status.ListSizeTests` fails without the
change. The next release carries it.

## What this does not establish

- The draft's vectors are encodings, not signed tokens: for them the walk checks decoding, under
  a signature it made itself. Only the Section 8.2 example and the library's tokens check a
  signature someone else's key made, and the library's key is generated by this walk too.
- It decides tokens it was handed. It does not fetch a list over HTTP (`decide_by_fetching`) or
  check the credential that names the list, and nobody outside Polaris ran it.
- It covers the JWT form only. The CBOR (CWT) form of the draft is not implemented here.
